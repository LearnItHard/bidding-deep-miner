# Agent 连续性：保持挖掘持续运行

大型招投标项目挖掘可能需要多轮搜索和长时间的网页抓取。Agent 连续性机制确保挖掘不会中途停止。

## MANDATORY: 在任何挖掘工作前先设置心跳

心跳循环是**第一件事**。没有它，Agent 做完一个搜索就停了。

## Claude Code: /loop

**作为第一个动作立即运行：**

```
/loop 15m 继续招投标项目深度挖掘。读取 mining-state.yaml 和 findings.md。检查：当前搜索是否完成？有新的搜索结果待提取吗？置信度是否达标？如果一切正常，继续当前工作。如果卡住了（搜索无结果、置信度低），调整搜索策略或切换到新的关键词。永远不要停。更新 mining-state.yaml、mining-log.md 和 findings.md。当有重要发现（发现关键证据、工艺推断置信度达标）或完成报告时，通过进度报告告知用户。
```

### 每个 tick 发生了什么

`/loop` 每 15 分钟触发一次：

1. **读取状态** — `mining-state.yaml` 和 `findings.md`，回想当前进度
2. **检查健康** — 搜索是否完成？有没有错误？信心是否足？
3. **如果正常** → 继续当前工作（不要重新开始或重新规划）
4. **如果卡住** → 退一步，调整策略，然后继续
5. **禁止空转** — 永远不要闲着

tick 是提醒，不是阶段边界。如果上一轮的工作没做完，继续做。

### 当搜索/抓取耗时超过 15 分钟

这很正常。在下一个 tick：
- 如果正在 `fetch_webpage` 抓取页面 → 检查是否完成
- 如果还在抓取 → 等待，并行做轻量工作（整理已有结果、更新状态文件）
- 不要重复或重启搜索

### 上下文恢复

tick 之间的主要记忆是 `mining-state.yaml` 和 `findings.md`。每次搜索和提取后更新它们。如果丢失上下文，读取这两个文件加上 `mining-log.md` 来重建当前进度。

## 挖掘状态作为唯一真相来源

| 文件 | 用途 | 更新频率 |
|------|------|---------|
| `mining-state.yaml` | 机器可读的状态 | 每次搜索、提取、分析后 |
| `mining-log.md` | 决策时间线 | 每次重要行动后 |
| `findings.md` | 叙事性理解 + 项目记忆 | 每次外环综合后 |
| `searches/` | 原始搜索结果 | 每次搜索后 |
| `evidence/` | 提取的证据数据 | 每次提取后 |

心跳循环（`/loop`）只是触发器。工作区文件是记忆。保持它们是最新的。
